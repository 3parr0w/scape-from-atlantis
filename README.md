# فرار از آتلانتیس — نسخه‌ی آنلاین

بازی دیجیتال *Survive: Escape from Atlantis* برای ۲ تا ۴ نفر، با دو حالت: **بازی محلی** (یک صفحه، نوبتی) و **بازی آنلاین** (هر نفر روی دستگاه خودش).

## اجرا (سریع)
نیازمندی: Node.js نسخه‌ی ۱۸ یا بالاتر. کد TypeScript است و قبل از اجرا به JavaScript ساخته می‌شود.

```bash
npm install
npm run build              # type-check + ساخت public/index.html و dist/
npm start                  # ساخت + اجرا روی http://localhost:3000
```

- `npm run build` کل اپ را با `esbuild` در یک فایل مستقل (`public/index.html`) جمع می‌کند و سرور و تست‌ها را با `tsc` در `dist/` می‌سازد.
- `npm run typecheck` فقط بررسی نوع‌ها (strict) روی `src/` و `server.ts` است.

### روی یک وای‌فای / شبکه‌ی محلی
۱. `npm start` را روی یک لپ‌تاپ اجرا کن.
۲. آی‌پی لپ‌تاپ را پیدا کن (`ipconfig` در ویندوز، `ifconfig` یا `ip a` در مک/لینوکس)، مثلاً `192.168.1.20`.
۳. بقیه با گوشی یا لپ‌تاپ خودشان `http://192.168.1.20:3000` را باز می‌کنند. هات‌اسپات گوشی هم جواب می‌دهد.
۴. یک نفر «بازی آنلاین ← ساخت اتاق» را می‌زند و کد ۵ حرفی (یا لینک) را به بقیه می‌دهد؛ بقیه با «ورود» وصل می‌شوند. وقتی همه‌ی صندلی‌ها پر شد بازی خودکار شروع می‌شود.
اگر فایروال سیستم اجازه ندهد، پورت ۳۰۰۰ را باز کن.

### روی اینترنت
هر هاستی که Node یا Docker اجرا کند جواب می‌دهد (Render، Railway، Fly.io، یک VPS). فایل `Dockerfile` و `render.yaml` آماده است.
- دستور شروع: `npm start`؛ پورت از متغیر `PORT` خوانده می‌شود.
- بهتر است هاست HTTPS بدهد؛ کلاینت خودش `wss://` را انتخاب می‌کند.
- متغیر `DATA_FILE` مسیر ذخیره‌ی اتاق‌ها را عوض می‌کند (پیش‌فرض `data/rooms.json`). روی هاست‌هایی که دیسک موقت دارند، برای ماندن بازی‌ها بعد از ری‌استارت یک دیسک دائمی وصل کن.

> **مهم: روی Vercel (و هر هاست serverless) بازی آنلاین درست کار نمی‌کند.**
> اتاق‌ها در حافظه‌ی همان پروسه‌ی سرور نگه داشته می‌شوند و بازی به یک نمونه‌ی واحد و همیشه‌روشن نیاز دارد. Vercel برای هر اتصال یک نمونه‌ی تابع جدا بالا می‌آورد؛ اتاقی که روی یک نمونه ساخته شده روی نمونه‌ی دیگر وجود ندارد و دوستت با خطای «اتاقی با این کد یافت نشد» روبه‌رو می‌شود. کلاینت حالا چند بار ورود را دوباره امتحان می‌کند، ولی این فقط یک مسکّن است.
> راه‌حل درست: همین پروژه را روی Render/Railway/Fly.io یا یک VPS (یک نمونه) اجرا کن، یا لوکال اجرا کن و با یک تونل (مثل Cloudflare Tunnel) لینک بده. با `render.yaml` می‌توانی در Render یک‌کلیکی دیپلوی کنی؛ آدرس `https://<service>.onrender.com` را به‌جای آدرس Vercel برای دوستانت بفرست.

## ساختار
```
src/engine.ts   قوانین بازی؛ بدون DOM و بدون I/O (هم در مرورگر، هم در Node)، با تایپ‌های کامل
src/ui.ts       رابط: فقط نمایش و کلیک؛ حالت محلی و آنلاین
src/shell.html  قالب صفحه (CSS) + جای‌نگهدار /*BUNDLE*/
server.ts       سرور: اتاق‌ها، صندلی‌ها، اتصال دوباره، نمای مخصوص هر بازیکن
public/index.html  خروجی ساخته‌شده (shell + bundle)، یک فایل مستقل
dist/           خروجی ساخته‌شده‌ی سرور و تست‌ها (ESM)
tools/          build.mjs، bot.ts، fuzz.ts، online-test.ts، ui-smoke.ts، engine-test.ts، server-test.ts
```

## موبایل
- تخته با یک انگشت جابه‌جا می‌شود و با دو انگشت (pinch) یا دکمه‌های ＋ − بزرگ‌نمایی می‌شود؛ دکمه‌ی ⤢ کل تخته را برمی‌گرداند. روی کامپیوتر چرخ ماوس هم زوم می‌کند.
- در حالت عمودی، نمایش اولیه روی جزیره بزرگ شده؛ جزیره‌های امن گوشه‌ها را با کشیدن یا ⤢ ببین.
- نوار وضعیت و دکمه‌ها پایین صفحه است (دسترسی با شست)، امتیاز بازیکن‌ها یک ردیف فشرده در بالاست و گزارش بازی جمع‌شدنی است.
- در حالت افقی گوشی، پنل کنترل کنار تخته می‌آید.
- هدف لمسی مهره‌ها و دکمه‌ها بزرگ‌تر شده (حداقل ۴۴ پیکسل برای دکمه‌ها).

## گرافیک و انیمیشن
- همه‌ی مهره‌ها نقاشی برداری (SVG) هستند، نه اموجی: آدمک (به رنگ بازیکن)، قایق بادبانی، مار دریایی، کوسه، نهنگ، جزیره‌ی امن و لنگر. روی هر دستگاهی یکسان دیده می‌شوند. کد آن‌ها در `src/gfx.ts` است.
- آیکون‌های رابط هم برداری‌اند (`gfx.ts`): بزرگ‌نمایی، کوچک‌نمایی، اندازه‌ی صفحه، صدا/بی‌صدا، هشدار، برگردان، تاس، نشانی نوبت و جام برنده. در لاگ بازی هم به‌جای اموجی، همان نقاشی کاشی و موجودات دیده می‌شود. هیچ اموجی یا فایل تصویری در بازی نیست.
- مهره‌ها و قایق‌ها نرم جابه‌جا می‌شوند؛ موجودات روی آب بالا و پایین می‌روند و هنگام رسیدن موج می‌اندازند. مهره‌ی غرق‌شده یا از دست‌رفته حباب می‌دهد و فرو می‌رود، مهره‌ی نجات‌یافته ستاره می‌پاشد.
- کاشی برداشته‌شده از تخته بلند می‌شود و محو می‌شود. گرداب می‌چرخد و آتشفشان جرقه و نور می‌دهد.
- تاس با انیمیشن می‌غلتد. دریا موج متحرک دارد و دور جزیره کف و روشنایی کم‌عمق است.
- صدا (بدون فایل صوتی) با WebAudio در `src/sfx.ts` ساخته می‌شود. دکمه‌ی بلندگو کنار دکمه‌های زوم، آن را قطع و وصل می‌کند (آیکونش با وضعیت صدا عوض می‌شود) و انتخاب در مرورگر یادآوری می‌شود. اگر دستگاه «کاهش حرکت» را روشن کرده باشد، انیمیشن‌های بی‌پایان خاموش می‌شوند.
- تخته‌ی SVG حالا دو لایه دارد: لایه‌ی ثابت دریا و `#fg` که هر رندر دوباره ساخته می‌شود، به‌علاوه‌ی `#fx` برای جلوه‌های موقت. تست `ui-smoke` به همین دلیل `#fg` را بررسی می‌کند.

## رابط بازی (بازیکن‌ها، مرحله‌ها، کاشی‌ها)
- **کارت بازیکن:** بالای صفحه برای هر نفر یک کارت هست با آواتار رنگی، نام، برچسب «تو / نوبت / قطع» و شمارنده‌های نجات، خطر، تلف و تعداد کاشی دستی. کارت بازیکنی که نوبتش است قاب رنگی دارد.
- **نام در بازی محلی:** بعد از انتخاب تعداد بازیکن، برای هر نفر یک نام (اختیاری) وارد می‌شود. نام‌ها در همه‌جا (وضعیت، گزارش، صفحه‌ی «صفحه را بدهید»، پنجره‌ی دفاع) استفاده می‌شوند. نام‌ها از `<>&"'` پاک می‌شوند و حداکثر ۱۶ حرف‌اند. اگر خالی بماند، نام رنگ گذاشته می‌شود.
- **نوار مرحله:** بالای پنل پایین، نام بازیکن فعلی و چهار مرحله‌ی نوبت (کاشی، حرکت، برداشت، تاس) دیده می‌شود. مرحله‌ی فعلی پررنگ است و در مرحله‌ی حرکت، حرکت‌های باقی‌مانده با نقطه نشان داده می‌شود. هنگام چیدن اولیه، دو مرحله‌ی «مهره‌ها» و «قایق‌ها» را نشان می‌دهد.
- **کاشی‌های دستی به‌شکل کارت:** هر کاشی یک کارت با نقاشی برداری و نام است. کاشی‌های قابل‌استفاده آبی‌اند، دفاعی‌ها زرد با برچسب «دفاعی». لمس یک کارت توضیحش را نشان می‌دهد و در مرحله‌ی اول، آن را برای استفاده انتخاب می‌کند. کارت‌ها همیشه دیده می‌شوند (حتی وقتی نوبتت نیست)، پس می‌دانی چه داری. حریف‌ها فقط تعداد کاشی‌ها را می‌بینند.
- **چیدن اولیه:** مهره‌های باقی‌مانده به‌صورت کارت نمایش داده می‌شوند. «نمایش اعداد من» عددها را نشان می‌دهد.
- **دکمه‌ها:** دکمه‌ی اصلی هر مرحله پهن و پررنگ است («بدون کاشی ادامه بده»، «پایان حرکت‌ها»، «ریختن تاس»…) و «برگردان» کنار آن.
- **پنجره‌ها:** نمایش محتوای کاشی، پنجره‌ی دفاع و پایان بازی از نقاشی کارت استفاده می‌کنند، نه اموجی.

## چطور کار می‌کند
- **سرور مرجع است.** وضعیت بازی فقط روی سرور است. کلاینت یک اکشن می‌فرستد (`{t:'movePerson',p:3,to:'7,5'}`)؛ سرور با `engine.apply` بررسی و اجرا می‌کند و به هر بازیکن `engine.view` مخصوص خودش را می‌فرستد.
- **اطلاعات مخفی هرگز به کلاینت دیگران نمی‌رسد:** محتوای کاشی‌های روی تخته، عدد مهره‌های حریف و کاشی‌های دستی حریف. فقط کسی که کاشی را برمی‌دارد، رویداد `reveal` را می‌گیرد.
- **دفاع** (دفع کوسه/نهنگ) یک پنجره‌ی تصمیم فقط برای بازیکن مربوطه است. پنجره برای همه‌ی بازیکنان درگیر نمایش داده می‌شود، چه کاشی داشته باشند چه نه، تا از روی آن نشود حدس زد کی کاشی دارد.
- **اتصال دوباره:** هر بازیکن یک توکن دارد (در `localStorage` مرورگر). اگر صفحه بسته یا اینترنت قطع شود، با «ادامه‌ی بازی قبلی» یا خودکار به همان صندلی برمی‌گردد.
- تاس با بذر ذخیره‌شده در وضعیت ریخته می‌شود و فقط سرور آن را می‌ریزد.
- «برگردان» (undo) فقط برای حرکت‌های همان نوبت است و برای بازیکن فعلی.

### پروتکل WebSocket
کلاینت ← سرور: `{type:'create',n,name}` · `{type:'join',code,name}` · `{type:'rejoin',code,token}` · `{type:'action',a}`
سرور ← کلاینت: `joined{code,seat,token}` · `lobby{code,n,names}` · `state{view,events,names,connected}` · `error{msg}`

## تست
```bash
npm test
```
`npm test` اول `npm run build` را اجرا می‌کند و بعد تست‌های ساخته‌شده در `dist/` را.
- `engine-test.ts`: آزمون‌های دقیق قوانین روی موتور (۴۵ مورد): چیدن، نوبت‌ها، حرکت مردم/قایق، کاشی‌ها، موجودات، پنجره‌ی دفاع، پنهان‌ماندن اطلاعات و امتیازدهی؛ به‌همراه ۲۰۰ بازی تصادفی درون‌موتوری.
- `server-test.ts`: بررسی پاک‌سازی ورودی‌ها (نام بازیکن) و ساختار کد اتاق.
- `fuzz.ts`: ۳۰۰ بازی کامل تصادفی روی موتور (باید همه تمام شوند، بدون خطا و بدون نشت محتوای کاشی).
- `online-test.ts`: سرور واقعی + ۳ کلاینت WebSocket، یک بازی کامل از طریق شبکه، قطع و وصل شدن یک بازیکن وسط بازی، و بررسی اینکه رازها به دیگران نمی‌رسد.
- `ui-smoke.ts`: بررسی سریع رابط با DOM ساختگی روی خروجی ساخته‌شده (بدون مرورگر).

## محدودیت‌های فعلی
- یک نمونه‌ی سرور (وضعیت اتاق‌ها در حافظه است و روی فایل ذخیره می‌شود). برای چند سرور باید ذخیره‌ی مشترک (مثلاً Redis) اضافه شود.
- ورود/حساب کاربری ندارد؛ هر کسی کد اتاق را بداند تا قبل از شروع می‌تواند وارد شود. بعد از شروع فقط با توکن صندلی می‌شود برگشت.
- اتاق‌های ۲۴ ساعت بی‌فعالیت پاک می‌شوند.
- قوانین اختیاری بازی هنوز پیاده نشده‌اند و نمایش بازی در `ui.ts` و گرافیک برداری در `gfx.ts` است.
